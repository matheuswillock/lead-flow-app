## Issues Criticos (Corrigir Imediatamente)

### 1. Homepage sem conteudo HTML estatico para crawlers

- **Observacao:** A homepage serve um shell SPA do Next.js sem headings, texto, imagens ou links renderizados server-side. `curl` retorna apenas bundles CSS/JS e meta tags. Word count: 9 palavras.
- **Por que importa:** Googlebot processa JavaScript mas deprioritiza conteudo JS-only. Outros motores de busca (Bing, Yandex) e crawlers de IA podem ver uma pagina vazia. Esta e a pagina de maior trafego com `priority: 1.0` no sitemap.
- **Dependencia:** Desbloqueia todo o SEO on-page, indexacao de conteudo e fluxo de link equity interno.
- **Teste de verificacao:** `curl -s https://www.corretorstudio.com | wc -w` — se <100 palavras, o problema persiste.
- **Indicador de monitoramento:** Google Search Console > "Paginas" > "Descobertas - nao indexadas no momento".
- **Correcao:** Habilitar SSR ou SSG para a homepage no Next.js (`getStaticProps` / `generateStaticParams` / RSC com streaming). Todas as paginas publicas devem retornar HTML completo na primeira resposta.

### 2. Sem tag H1 na homepage (HTML estatico)

- **Observacao:** O HTML estatico tem `<title>` mas nenhuma tag `<h1>`. A hierarquia de headings esta vazia.
- **Correcao:** Garantir que o H1 renderize server-side: `"Corretores comuns mandam cotacoes. Os de ALTA PERFORMANCE usam Corretor Studio."` (conforme contrato do hero na CLAUDE.md).
- **Teste de verificacao:** `curl -s URL | grep -oP '<h1[^>]*>.*?</h1>'` deve retornar o headline do hero.

### 3. Sem Schema.org na homepage

- **Observacao:** Zero `<script type="application/ld+json">` na homepage. Paginas de recursos tem BreadcrumbList + FAQPage (bom), mas a homepage — a pagina mais importante — nao tem nada.
- **Correcao:** Adicionar no minimo:
  - `SoftwareApplication` schema (produto SaaS)
  - `Organization` schema (identidade da marca)
  - `WebSite` schema com `SearchAction` (se aplicavel)
  - `BreadcrumbList` para navegacao
- **Teste de verificacao:** Google Rich Results Test na homepage deve detectar os schemas.
- **Indicador de monitoramento:** Aba "Melhorias" do Search Console sendo populada.

### 4. Zero imagens no HTML estatico

- **Observacao:** Contagem de `<img>` na homepage: **0**. Todas as imagens sao carregadas via hydration JS. Motores de busca podem nao indexa-las e trafego de busca por imagens e perdido.
- **Correcao:** Imagens criticas (hero banner, screenshots do produto) devem renderizar server-side com atributo `alt` contendo keywords-alvo.

## Issues de Alta Prioridade (Corrigir em 1 Semana)

### 5. Meta descriptions ausentes nas paginas de recursos

- **Observacao:** Apenas a homepage possui meta description. As 6 paginas de recursos (crm-corretores-saude, pipeline-planos-saude, etc.) tem title tags mas nao tem `<meta name="description">`.
- **Por que importa:** Google pode gerar snippets automaticos que nao correspondem a sua mensagem.
- **Correcao:** Adicionar meta descriptions unicas, 150-160 caracteres, com keyword principal + CTA para cada pagina de recursos.

### 6. Headers de seguranca ausentes

- **Observacao:** Headers HTTP ausentes:
  - `Content-Security-Policy` — ausente
  - `X-Content-Type-Options` — ausente
  - `X-Frame-Options` — ausente
  - `Referrer-Policy` — ausente
  - `Permissions-Policy` — ausente
  - `Strict-Transport-Security` — presente (bom, 63072000s / ~2 anos)
- **Correcao:** Adicionar security headers via `next.config.js` ou `vercel.json`. Estes sao sinais de confianca.
- **Teste de verificacao:** `curl -sI URL` deve exibir todos os headers.

### 7. Timestamps lastmod identicos em todo o sitemap

- **Observacao:** Todas as 12 URLs possuem `lastmod: 2026-06-23T14:54:41.089Z` — claramente auto-gerado, nao refletindo atualizacoes reais de conteudo.
- **Por que importa:** Google usa `lastmod` para priorizar crawl budget. Timestamps identicos sinalizam metadados nao confiaveis.
- **Correcao:** Gerar `lastmod` dinamicamente baseado em datas reais de modificacao do conteudo/arquivo.
- **Teste de verificacao:** Apos correcao, valores de `lastmod` devem diferir entre paginas.

### 8. `llms.txt` incluido no sitemap com `changefreq: daily`

- **Observacao:** `llms.txt` e um arquivo machine-readable para crawlers de IA, nao uma pagina legivel por humanos. Incluir no sitemap XML com `priority: 0.6` despertica crawl budget.
- **Correcao:** Remover `llms.txt` do `sitemap.xml`. Ele e descoberto via robots.txt ou convencoes de well-known URI. Manter o arquivo em si — esta bem estruturado.

### 9. FAQPage schema — awareness de depreciacao

- **Observacao:** Paginas de recursos usam schema `FAQPage` (ex: em `/recursos/crm-corretores-saude`). Google retirou FAQ rich results para TODOS os sites em 7 de maio de 2026.
- **Acao:** NAO remover o schema FAQPage — ele ainda fornece valor para citacao por IA (crawlers LLM o parseiam). Mas NAO esperar rich results nos SERPs. Nivel: Informativo.

## Issues de Media Prioridade (Corrigir em 1 Mes)

### 10. Baixa densidade de links internos na homepage

- **Observacao:** O HTML estatico tem apenas 1 link interno (favicon). Nenhuma navegacao, nenhum link de rodape, nenhum link de conteudo renderiza server-side. Link equity interno nao pode fluir.
- **Correcao:** Garantir que navegacao (recursos, subscribe, paginas legais) e links de conteudo renderizem server-side. Meta: 10-20 links internos na homepage.

### 11. Tag `meta keywords` presente mas obsoleta

- **Observacao:** Homepage tem `<meta name="keywords" content="crm para corretores de saude,...">`. Google nao usa esta tag desde 2009.
- **Correcao:** Remover ou ignorar. Baixa prioridade, mas remover ruido melhora higiene do codigo.

### 12. Sem tags `hreflang`

- **Observacao:** Site e apenas pt-BR. Sem tags `hreflang` presentes.
- **Acao:** Nao critico para site de lingua unica. Se planeja expandir para Portugal (pt-PT) ou mercados em espanhol, adicionar `hreflang` nesse momento. Sem acao agora.

### 13. Alt text da OG image e generico

- **Observacao:** `og:image:alt` e "Logo do Corretor Studio" — deveria descrever a proposta de valor, nao apenas "logo."
- **Correcao:** Mudar para algo como "Corretor Studio - CRM para corretores de saude com pipeline Kanban e metricas de conversao"

### 14. Sem blog ou estrategia de content hub

- **Observacao:** As 6 paginas de recursos sao bom conteudo pilar, mas nao ha blog, nao ha article schema, nao ha cadencia regular de publicacao.
- **Correcao:** Considerar adicionar uma secao `/blog` com artigos targetando keywords e linkando para paginas de recursos. Isso aumentaria dramaticamente o potencial de trafego organico.
- **Indicador de monitoramento:** Crescimento de impressoes no Google Search Console mes a mes.

## Issues de Baixa Prioridade (Backlog)

### 15. Regras redundantes no robots.txt

- Os dois blocos de user-agent (wildcard + bots nomeados) possuem regras identicas. Consolidar em um unico bloco `User-Agent: *` ou diferenciar se a intencao e ter niveis de acesso diferentes.

### 16. Sem `manifest.json` / sinais de PWA

- Nao critico para SEO mas ajuda com engajamento mobile e potenciais prompts de instalacao de Web App.

### 17. Cache-Control header e `must-revalidate`

- Paginas estaticas deveriam usar janelas de cache mais longas. Vercel CDN ja lida bem com isso (`X-Vercel-Cache: HIT`), mas considerar configurar `s-maxage` para caching de edge mais longo.

## Recomendacao de Setup Google APIs

Para monitoramento contínuo, configurar credenciais Google API:

```bash
# Definir chave PageSpeed/CrUX API
export GOOGLE_API_KEY="sua-chave"

# Ou criar arquivo de configuracao
mkdir -p ~/.config/claude-seo
echo '{"api_key": "sua-google-api-key"}' > ~/.config/claude-seo/google-api.json
```

Isso habilita dados de campo CWV, status de indexacao de URLs e analise de trafego organico em auditorias futuras.
