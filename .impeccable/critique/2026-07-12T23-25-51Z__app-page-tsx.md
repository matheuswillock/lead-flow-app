## Anti-Patterns Verdict

The initial implementation failed visually in dark-mode environments because the landing inherited global app theme tokens. That made the hero dark, low-contrast and visibly unlike the approved mockup. After the fix, `.landing-page` owns a light-only token scope, so `bg-card`, `text-primary`, borders, form fields and CTAs resolve to the intended landing palette regardless of system theme.

Deterministic scan still reports `overused-font` for Inter in `app/globals.css`. This is a false positive for this project because `DESIGN.md` explicitly defines Poppins + Inter as the Corretor Studio typography stack.

## Overall Impression

The biggest issue was not the component structure; it was theme leakage. The landing was technically using shared tokens, but for a light-only marketing page inside a system-themed app, that produced the wrong visual world. The page now behaves like the mockup: warm light hero, orange CS mark, and two-column hero beginning at the mockup's tablet/desktop breakpoint.

## What's Working

- Product imagery is real and local, which supports trust and avoids placeholder marketing.
- The hero copy preserves the required contract headline.
- The page has focused sections and keeps the demo form instead of introducing a dead CTA path.

## Priority Issues

### [P0] Landing inherited app dark mode
Why it matters: In dark system mode, the first viewport became dark and low-contrast, breaking brand intent and readability.
Fix: Added light-only semantic token overrides on `.landing-page`, including `--card`, `--background`, `--foreground`, `--primary`, `--muted`, `--border`, and landing-specific text tokens.
Suggested command: `$impeccable audit app/page.tsx`

### [P1] Hero breakpoint did not match the mockup
Why it matters: Around 920-1024px, the product screenshot dropped below the fold while the reference still shows text and product side by side.
Fix: Changed the hero grid and nav visibility to start at `min-[920px]` instead of waiting for Tailwind `lg`.
Suggested command: `$impeccable adapt app/page.tsx`

### [P1] Header/footer logo did not match the approved visual language
Why it matters: The screenshot showed the app icon instead of the compact `CS` brand mark used in the mockup, making the landing feel like a different design.
Fix: Replaced header/footer image logo with a reusable `.landing-logo-mark` CSS mark.
Suggested command: `$impeccable critique app/page.tsx`

### [P2] Detector flags Inter as generic
Why it matters: This can be an AI-slop signal in greenfield work, but changing it would violate the existing brand system.
Fix: No code change; treated as false positive because `DESIGN.md` mandates Poppins + Inter.
Suggested command: `$impeccable document DESIGN.md`
